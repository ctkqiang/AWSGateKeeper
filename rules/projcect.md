# AWS Gateway – 安全审计规则

## 规则 1：IAM_VENDOR_EXTERNALID_REQUIRED

| 属性               | 值 |
|--------------------|-----|
| **规则 ID**         | `IAM_VENDOR_EXTERNALID_REQUIRED` |
| **规则名称**        | 跨账户 IAM 角色必须强制使用唯一的 ExternalId |
| **风险等级**        | 严重（CRITICAL） |
| **描述**            | 任何信任外部 AWS 账户（即不属于同一企业或业务单元的 AWS 账户）的 IAM 角色，必须包含一个条件，要求提供唯一且非空的外部标识符。 |
| **理由**            | 若不要求提供外部标识符，攻击者在攻陷另一个 AWS 账户后即可滥用此信任关系。这是防止"混淆代理问题"（confused deputy problem）的标准安全控制措施。 |
| **受影响资源**      | 信任策略中允许外部 AWS 委托人的 IAM 角色。 |
| **检测逻辑**        | 审计将检查账户中的每一个 IAM 角色。对于允许外部 AWS 账户访问的角色，会检查其信任策略是否包含强制要求唯一外部标识符且值非空的条件。 |
| **合规示例**        | 信任策略中包含一个条件，要求提供特定的外部标识符值（例如供应商唯一的密钥）。 |
| **不合规示例**      | 信任策略允许外部 AWS 账户访问，但未包含任何条件，或外部标识符为空。 |
| **修复措施**        | 在信任策略中添加所需的条件。生成一个新的唯一外部标识符，并通过安全渠道与外部账户所有者共享。 |
| **误报处理**        | 仅信任 AWS 服务（而非外部账户）的角色可忽略。若内部信任策略允许，信任同一企业组织内账户的角色可排除在外。 |

## 规则 2：COGNITO_PRIVILEGED_EXTERNAL_USERS

| 属性               | 值 |
|--------------------|-----|
| **规则 ID**         | `COGNITO_PRIVILEGED_EXTERNAL_USERS` |
| **规则名称**        | 高权限 Cognito 用户组中不得存在外部用户 |
| **风险等级**        | 高（HIGH） |
| **描述**            | 电子邮件域不在允许的企业域名列表中的用户，不得属于任何预定义的高权限用户组。 |
| **理由**            | 外部用户（如供应商或承包商）应仅拥有受限且可审计的访问权限。将其置于管理员角色中违反了最小权限原则，增加了未授权操作或数据泄露的风险。 |
| **受影响资源**      | 用户在被视为高权限的 Cognito 用户池用户组中的成员身份。 |
| **检测逻辑**        | 审计列出账户中的所有用户池，然后查找名称匹配高权限模式的用户组（例如 Admin、SuperUser、Operator）。对每个此类用户组，获取其成员列表，提取用户的电子邮件地址，并将电子邮件域与允许的企业域名列表进行比对。 |
| **合规示例**        | 电子邮件地址以 `@enterprise.com` 结尾的用户是 Admin 用户组的成员。 |
| **不合规示例**      | 电子邮件地址以 `@external-consultant.com` 结尾的用户是 Admin 用户组的成员。 |
| **修复措施**        | 将该外部用户从高权限用户组中移除，或将其移至仅具有只读权限的用户组。若业务需要特定外部用户拥有提升的访问权限，应创建一个权限严格限定范围的自定义用户组，并将其从高权限模式列表中排除。 |
| **误报处理**        | 拥有企业电子邮件域的用户会被接受，即使其属于子公司域名。若合法的外部用户确实需要担任管理员，应在本次审计之外另行记录正式的例外情况。 |

## 执行与报告

- **审计频率**：每日执行，时间可配置。
- **发现物存储**：所有发现物均存储在中央数据库表中，包含以下属性：账户 ID、时间戳、公司或业务单元名称、风险等级、资源 ARN 和违规详情。
- **严重级别**：
  - 严重（CRITICAL）—— 分配给缺少外部标识符的 IAM 角色（规则 1）。
  - 高（HIGH）—— 分配给处于高权限 Cognito 用户组中的外部用户（规则 2）。
- **告警通知**：严重级别的发现物可通过企业告警系统触发即时通知。

## 规则维护

- 规则由审计引擎进行评估。添加新规则需要扩展审计逻辑。
- 高权限用户组名称列表和允许的企业域名列表可通过环境设置进行配置；常规更新无需修改代码。
- 规则版本在源代码管理仓库中进行追踪。
